# Internationalisation

Supported: `en` (default and fallback), `uk`, `pl` (spec 026). The one list is
`SUPPORTED_LANGUAGES` in `src/domain/language.ts`; a new language adds its id there and a
`locales/<id>.json` file.

## Files

- `locales/en.json`, `locales/uk.json`, `locales/pl.json` — one flat-namespaced JSON per language,
  shared by renderer (react-i18next) and main (menu, native dialogs).
- Keys are `area.element[.state]`, in English, camelCase segments:
  `board.addApplication`, `stages.hr_interview`, `notes.deleteConfirm.title`.

## Rules

1. No literal user-visible strings in components or main-process menus/dialogs.
2. Every key exists in every file. `tests/unit/i18n.test.ts` fails CI on missing
   or extra keys and on mismatched `{{interpolation}}` variables.
3. Plurals use i18next plural suffixes. Ukrainian needs `_one`, `_few`, `_many`
   (and `_other`); English needs `_one`, `_other`.
   Example: `card.notesCount_one: "{{count}} note"`.
4. Dates: `Intl.DateTimeFormat(lang)`; relative times: `Intl.RelativeTimeFormat(lang)`.
   Never build date strings manually.
5. User content (titles, companies, notes) is never translated.

## Language resolution

1. `settings.language` if set.
2. Otherwise the first two letters of `app.getLocale()`: `uk` → `uk`, `pl` → `pl`, else `en`.
3. Changing language: renderer calls `setLanguage` → main persists, rebuilds the
   native menu, and both sides switch without restart.
